GIT FORENSICS - проверка дат файла в Git
=========================================

Показывает, когда файл появился в истории Git, и ищет несостыковки в датах
коммитов: будущие даты, расхождение даты автора и коммита, нарушение порядка
родитель/потомок, расхождение с reflog. Работает только на вашем компьютере,
ничего никуда не отправляет.

Нужно: Python 3.7+ (python.org, отметьте "Add python.exe to PATH") и Git.

Запуск
------
1. Распакуйте архив.
2. Дважды щёлкните start.bat - откроется http://127.0.0.1:8765
3. Введите путь к папке репозитория и имя файла (относительно корня
   репозитория), нажмите "Проверить файл".
4. Остановить: закройте чёрное окно или нажмите Ctrl+C.

Из командной строки (без интерфейса), в папке репозитория:
   py путь\к\git_forensics.py файл.txt
   py путь\к\git_forensics.py файл.txt -o отчёт.json
   py путь\к\git_forensics.py файл.txt -C путь\к\репозиторию

Версия для другого человека (один файл GitForensics.exe)
--------------------------------------------------------
Другой человек без Python может запустить только готовый .exe.
Соберите его один раз на своём компьютере: дважды щёлкните build_exe.bat
(нужен интернет). Через минуту появится dist\GitForensics.exe. Отправьте
этот один файл. Получателю нужен только Git. Двойной щелчок по
GitForensics.exe открывает интерфейс в браузере.
Если Windows покажет предупреждение SmartScreen, выберите "Подробнее" ->
"Выполнить в любом случае": файл не имеет цифровой подписи.

Файлы
-----
build_exe.bat     сборка единого GitForensics.exe
start.bat         запуск двойным щелчком
ui_server.py      локальный веб-интерфейс (только 127.0.0.1)
git_forensics.py  ядро анализа

test_git_forensics.py  39 тестов ядра и веб-интерфейса
   Запуск:  py -m unittest test_git_forensics -v

Что изменено относительно прежней версии ядра
---------------------------------------------
- Быстродействие: метаданные коммитов и их родителей запрашиваются пачками,
  а не по одному (для истории в 60 коммитов — примерно 13 запусков git
  вместо ~120). Весь анализ работает заметно быстрее на длинных историях.
- Интерфейс больше не меняет рабочую папку процесса: папка репозитория
  передаётся напрямую, поэтому параллельные запросы не мешают друг другу.
- Устойчивость: если метаданные родительского коммита получить не
  удалось (например, объект отсутствует в репозитории), анализ не падает,
  а завершается частичным отчётом со статусом partial и записью
  parent_check_incomplete в блоке «Ограничения метода». Самостоятельный
  обход истории с отсутствующими объектами git может не поддерживать.
- Надёжность: имена файлов с символами *. [] теперь трактуются буквально.
- В веб-интерфейсе усилена проверка входных запросов: посторонние сайты,
  не-JSON запросы и слишком большие тела отклоняются; лимит тела — 100 КБ.
- Командная строка: новая опция -C/--repo задаёт папку репозитория
  без перехода в неё. Если git не найден или не отвечает, выводится
  понятная ошибка вместо сырого текста.
- Неподписанный коммит по-прежнему определяется по самому объекту коммита
  и получает статус "unsigned" (раньше на Windows мог быть
  "verification_failed").
- Тестов стало 39 (было 18): добавлены проверки параллельного анализа,
  спецсимволов в именах, недоступных родителей и защиты HTTP-эндпоинта.

Ограничения
-----------
Даты в Git задаёт клиент. Отсутствие аномалий не доказывает подлинность
истории, а наличие аномалий не доказывает подделку.
